The wiki-db-agent refuses the request at the policy-gate phase (AGENT.md,
section "EXECUTION PHASES", step 3). The request parses to:

  { "action": "query", "env": "production", "sql": "DROP TABLE users" }

but the agent classifies the SQL as DDL before any connection step and
returns a pre-connect DENY. No CLI subprocess was dispatched against the
production environment; the policy gate was invoked directly (offline).

    import { Policy, classifySqlKeywords } from
      '/Users/narayan/src/doc-wiki/agents/lib/wiki_db/policy.js';
    const sql = 'DROP TABLE users';
    const op  = classifySqlKeywords(sql);

NOTE ON NON-INVOCATION OF db_query.js:
`node agents/wiki-db-agent/scripts/db_query.js --env production
--sql "DROP TABLE users"` was deliberately NOT executed. That CLI would
call `getConnection(envName)` BEFORE `policy.checkQuery(sql)` in
`runWithEnv`, which would attempt a TCP connect to the (unreachable)
production host. Per the AGENT.md CRITICAL RULES ("NEVER execute DROP,
CREATE, ALTER, TRUNCATE, GRANT, REVOKE — hard DENY"), the agent's
contract is to refuse DDL at the agent layer without ever dispatching
the CLI. The verification above exercises the same `policy.checkQuery`
that the CLI uses, without touching the driver/connection path.
